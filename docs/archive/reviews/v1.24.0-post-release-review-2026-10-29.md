## 二、fetchers 域

### P1-1　cb / ipo 的 `truncated` 标志 off-by-one → 静默截断且不告警

`scripts/fetchers/cb/eastmoney_cb.py:71`、`scripts/fetchers/ipo/eastmoney_ipo.py:76`

```python
truncated = page - 1 > MAX_PAGES   # 退出时 page == MAX_PAGES+1 → page-1 == MAX_PAGES → 恒 False
```

同批提交的 `ths_limit_up.py:89` 用的是正确写法 `total_pages > MAX_PAGES`——三个域三种写法。
实测 cb 取 500/1000 条、ipo 取 150/500 条，`truncated` 均为 `False`，
`scripts/cb.py:40` 与 `scripts/ipo_calendar.py:48` 的"⚠ 已截断"告警永不触发。
cb 域 `total` 统计的是板块全量（含已退市/无行情），活跃仅 276 只 → **天天触发静默截断**。

**已修**：`truncated = total_pages > MAX_PAGES`，新增两个截断回归锚点。

### P1-2　降级链挂在 manager 单例上 → 血缘不可信

`scripts/common/fetcher_base.py:272-284` + `scripts/business/stock_analysis.py:124,128`

链挂在 manager 上、每次 `fetch()` 开头整体重置。个股行情与指数行情**并发共用同一
quote manager** → 指数的降级事件被贴到个股的"行情[...]"行上；缓存命中路径
（`scripts/data/__init__.py:110-119`）根本不进 manager → 链保留上一次请求的残留。
这正是"无降级时是否干净显示"被破坏的地方。

**未修**（需要改 manager 接口语义，涉及数据层契约，留待 v1.25）：链应按 `(code, manager)`
维度存储，或随 `fetch()` 返回值传递。

`_is_limit_or_suspended` 只在选股入场侧调用（`engine.py:271`），出场路径

**已修**：出场路径也检查跌停/停牌，出场顺延到下一个可交易日。

### P1-5　涨停跳过用 `i += 1` → 持有期网格永久错位

`engine.py:271-273` 逐日推进而非整段跳过，该股票的选股日相对其它股票永久偏移，
并连带破坏与基准持有期切块的逐期对齐（实测策略期起点 `07-31` 对上基准块 `08-13`，错位约 2 周）。

**已修**：改为 `i += holding_days` 整段跳过。

### P1-6　`round()` 银行家舍入 ≠ 交易所 ROUND_HALF_UP

`engine.py:642-643`。5 万次抽样实测：涨停多判 1.5%、跌停漏判 4.0%。

**已修**：新增 `_limit_price()` 用 `Decimal` + `ROUND_HALF_UP`。

### P1-7　`excess_sharpe` 与 `information_ratio` 公式完全相同 → 恒等

`scripts/backtest/metrics.py:170` vs `:184`，公式、输入、守卫条件一致 → 数值必然相等。
新增指标零信息量。

**已修**：excess Sharpe 改为「策略夏普 − 基准夏普」（风险调整口径），与 IR（跟踪误差口径）区分。

### P1-8　alpha 漏无风险利率，且代入已四舍五入的 beta

`metrics.py:180` 用 rf=0，而同文件 Sharpe 用 rf=3%（`metrics.py:98`）。实测偏差 1.19 pct-pt。

**已修**：改为 CAPM 截距 `(strat_mean − rf) − beta × (bm_mean − rf)`，beta 用未舍入值。

### P1-9　基准期按位置而非日期对齐 → 实测已错位

`metrics.py:167` 纯下标配对，`min()` 静默截断多余策略期。

**未修**（需要引擎侧回传期起始日期，改动面较大）：当前依赖 P1-5 的网格对齐修复来保证等价。

### P1-10　PSR 分母符号错误

`metrics.py:378`：`sqrt(1 − 0.5·SR²)` 应为 `sqrt(1 + 0.5·SR²)`（正态 γ4=3 → PLUS）。
高 SR 时分母被 `max(1e-12, …)` 钳到 ~0 → DSR 被强行推向 1.0（假阳性"通过"）。

**已修**：改 PLUS，新增手算锚点测试。

### P1-11　网格重复试验虚增 N，污染 SR0 与离群检测

`scripts/backtest/cli.py:171-175`：`step=0` 对每个因子都等于基准权重，
`step=-0.05` 对权重本就 0.05 的因子是 no-op → 24 行只有 14 个不同权重向量。
实测 SR0 抬高 0.13、median 拉低 0.2 → 离群检测误报。

**已修**：新增 `_distinct_trial_sharpes()` 按权重向量去重后再算 DSR。

### P1-12　失败运行的夏普按 0 计入试验分布

`cli.py:182`：`report.get("sharpe_ratio", 0)`。失败时返回 `{"error": ...}`，0.0 是"最差结果"，
拉大 `var_sr`、抬高 SR0。

**已修**：含 `error` 的报告直接跳过，不计入 trials。

## 四、experts 域

### P1-13　整组弃权被误判为"两极分化"

`experts/vote_engine.py:117-121`：`bull >= long_n - 1` 在 `long_n=0` 时恒真。
5 位长线全弃权 + 3 位短线一致看多 → 判"两极分化（3 看多 + 0 看空）"，方向翻成中性观望。
这正是弃权第四态本应避免的"沉默被当作反向信号"。

**已修**：极值判定加 `n > 0` 前置条件。

### P1-14　看空专家的 slugging 赔率为负

`experts/calibration.py`：赔率用**带符号**收益而非方向调整后收益。

**已修**：新增 `_directional_return()`，看空专家取反。

### P1-15　仓位钳制后分步建仓指令仍按钳制前仓位生成

**已修**：抽出 `_build_steps()`，钳制后重建。

### P1-16　单组模式完全绕过钳制与弃权过滤

**已修**：单组模式补齐弃权过滤与确定性钳制。

### P1-17　多轮结算时预测级字段永久为空

### P1-18　单窗口取价失败 → 样本静默丢失且预测被判定"已结算"

`calibration.py:481/502/552`：部分窗口取价失败时继续执行，失败专家不计入 events

### P1-20　cap 钳制不收敛 + 全部超 cap 时权重和丢失

### P1-21　回撤熔断基准用累计利润而非权益 → 亏损账户永不熔断

**已修**：支持权益口径（初始资金 + 累计利润），负权益段改用绝对值分母。

### P1-22　trades 排序假设与 TradeLog 相反

## 九、复盘：为什么 2210 个测试全绿却没拦住这些

本轮 33 个 P1 中，绝大多数对应的测试是**行为断言而非数学锚点**：

| 反模式 | 本轮实例 |
| --- | --- |
| 断言"字段存在"而非数值正确 | `assert "alphas" in result` —— excess_sharpe 与 IR 恒等照样通过 |
| 绕过生产调用方直接测被测函数 | `test_normalize_factors_missing.py` 直接构造 `parts_list` → 60 个用例全绿，生产仍填 0 |
| 用作者自造 fixture 断言实现自身约定 | `test_cb_fetcher.py` 断言 f127 双低公式 → 无法证伪单位口径 |
| 只测正向路径 | 涨跌停只测买入侧拒单，卖出侧零覆盖 |
| 测试断言固化了缺陷行为 | `test_calibration_card_samples.py` 把 `not in` 改成 `in`，反而失去列区分能力 |

**后续改技术模块的纪律**：新增断言必须能证伪——数学锚点（手算值）、边界值
（n=10/n=9）、排序无关性（同一输入不同顺序给同一结论）、端到端（从生产调用方进）。
