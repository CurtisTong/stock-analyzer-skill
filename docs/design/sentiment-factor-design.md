## 一、背景与一个必须先解决的设计矛盾

校准报告 3.2 的原始建议是：

> **情绪指标组**（赚钱效应（涨跌停比/中位数涨幅）、晋级率（连板晋级）、连板天梯、题材 5 日轮动）
> → 直接喂 screener 做第 16 个因子 `sentiment`；短线阵营 3 位专家辩论时引用

**但这四个指标全是市场级的**——同一天，全市场 5000 只股票取到的是同一个值。
而 screener 的因子机制是**横截面**打分：`normalize_factors_batch` 按截面分位排名
（`scripts/business/screening_service.py:635-673`）。

两者直接相乘的结果是：市场级情绪因子在截面上**零区分度**——归一化后所有股票同为
50.0 分，加权进 score 不改变任何两只股票的相对排名。换句话说，按原建议直接实现，
这个因子是**空转的**。

这与本轮复审刚修掉的"缺值当 0"是同一类错误的镜像：那次是缺失值被伪装成真实值参与
排名，这次是真实值被伪装成无区分度参与排名。两者都会让因子看起来"已落地"却毫无作用。

### 因此本方案的核心决策：情绪分两层落地

| 层 | 内容 | 落地位置 | 横截面区分度 |
| --- | --- | --- | --- |
| **个股级情绪** | 该股自身的情绪强度（连板高度 / 封板质量 / 题材热度 / 活跃度） | 新因子 `sentiment` | 有（这才是因子）|
| **市场级赚钱效应** | 全市场赚钱效应、晋级率、中位数涨幅、连板天梯分布 | 接入现有 `regime` 机制做权重 overlay | 无（本就市场级，不该当因子）|

个股级情绪因子 + 市场级 regime 维度，两者互补而非重复。

### 3.0 接口探明结论（2026-10-30 实测，推翻了原方案的两个假设）

实测东财 push2ex 三个池接口（`date=20261029`，`_PUBLIC_UT`）：

| 接口 | 可用 | 条数 | 关键发现 |
| --- | --- | --- | --- |
| `getTopicZTPool`（涨停池） | ✅ rc=0 | 39 | 字段含 `hybk`（行业板块）、`ltsz`（流通市值，元）、`lbc`（连板数）、`zbc`（炸板次数）、`fund`（封单额，元）、`hs`（换手率 %）|
| `getTopicZBPool`（炸板池） | ✅ rc=0 | 25 | 同款字段集（含 `ltsz`/`hybk`/`zbc`）|
| `getTopicDTPool`（跌停池） | ✅ rc=0 | 0 | 当日无跌停（正常）|

**推论 1：题材归一化问题已解决，不需要字符串切分。**
`hybk` 直接给出结构化行业板块名（实测值："汽车零部"、"专用设备"、"休闲食品"），
用它替代 ths 的 `reason_type` 字符串切分——后者需要把"机器人+数据中心温控"拆成
两个题材词，切分不准就引入噪声，而 `hybk` 是交易所侧已分类好的字段。
板块热度口径因此从"题材热度"改为"**板块热度**"（申万二级行业粒度）。

**推论 2：封单强度可直接算，不需要额外的市值源。**
`fund / ltsz` = 封单额占流通市值比例，字段自带。

**推论 3：炸板池真实可用**，无需退化为只用 zt_pool 的 zbc 字段。

**推论 4（负面）：封单占比的真实分布与拍脑袋的档位不符，已按实测重设。**
实测 64 个样本（涨停 39 + 炸板 25）的封单占比（占流通市值 %）分位：

```
p25 = 0.0000    p50 = 0.2244    p75 = 1.3634    p90 = 3.4697    max = 18.6505
```

p25 = 0 说明约四分之一样本 `fund = 0`——**必须区分"封单数据缺失"与"真的没有封单"**，
前者按缺失处理（该子项用中性），后者按 0 封单计（弱）。不区分会把数据缺失
当成"封不住"扣分。

`zbc`（炸板次数）实测分布：`0→15, 1→18, 2→13, 3→6, 4→3, 5→1, ≥6→8`（n=64），
即约 1/4 的样本炸板次数 ≥3。

**唯一必须新建的是历史快照库**——晋级率与题材 5 日轮动都需要历史序列，
而现有的 `zt_pool` 只取当日（`date` 参数可查历史单日，但无法批量回溯）。

## 三、数据层设计

### 3.1 快照内容

每日收盘后落一份快照（`scripts/data/sentiment_snapshots.json`）：

```json
{
  "version": 1,
  "snapshots": {
    "2026-10-29": {
      "limit_up_count": 68,
      "limit_down_count": 5,
      "broken_count": 21,
      "max_height": 6,
      "height_distribution": {"1": 45, "2": 12, "3": 6, "4": 3, "5": 1, "6": 1},
      "promotion_rate": 0.31,
      "median_chg_pct": 1.2,
      "sectors": {
        "专用设备": {"count": 3, "limit_up": 3, "broken": 1, "chg_median": 10.0},
        "汽车零部": {"count": 2, "limit_up": 1, "broken": 1, "chg_median": 9.9}
      },
      "stocks": {
        "sz002708": {"lbc": 4, "zbc": 17, "fund": 8538217, "ltsz": 10615600211.33,
                     "hs": 27.9, "sector": "汽车零部", "status": "limit_up"},
        "sz00xxxx": {"lbc": 0, "zbc": 2, "fund": 0, "ltsz": 3448280675.0,
                     "hs": 4.1, "sector": "休闲食品", "status": "broken"}
      }
    }
  }
}
```

字段说明：

| 字段 | 来源 | 用途 |
| --- | --- | --- |
| `limit_up_count` / `limit_down_count` | zt_pool + 跌停池 | 赚钱效应 |
| `broken_count` | 炸板池（东财 push2ex `zbgc`）| 封板质量的市场基线 |
| `max_height` / `height_distribution` | zt_pool 的 lbc 分布 | 连板天梯 |
| `promotion_rate` | **昨日快照的 stocks 集合** ∩ **今日涨停池** ÷ 昨日涨停数 | 晋级率 |
| `median_chg_pct` | 涨停池 zdp 的中位数 | 赚钱效应 |
| `sectors` | 涨停池 + 炸板池按 `hybk` 聚合（板块 → 涨停/炸板家数）| 板块热度 |
| `stocks` | 涨停池 + 炸板池逐股明细（`status` 区分涨停/炸板）| 个股级因子 |

### 3.2 保留策略

- 保留最近 **60 个交易日**（足够算 5 日/20 日轮动，且文件可控在几百 KB）
- 写入用 `portfolio/_file_utils.atomic_write`（原子写 + 文件锁），与 trade_log 同款
- 文件加入 `.gitignore`（含用户交易/情绪历史，不入库）

### 3.3 首次运行与历史不足的降级

这是必须提前定死的：**新装用户第一天没有历史**，此时

| 需要历史的指标 | 无历史时 |
| --- | --- |
| 晋级率 | 不可算 → `promotion_rate = None`，快照里留 `null` 而非 0（0 会被误读成"零晋级"）|
| 板块 5 日轮动 | 退化为**当日板块强度**（该板块当日涨停家数占全部涨停的比例），不做时序比较 |
| 连板天梯分布 | 当日即可算（不需要历史）|

降级必须在快照里显式标记（`"history_days": 0`），让消费方知道口径与完整口径不同。

## 四、因子口径设计

### 4.1 个股级情绪因子 `sentiment_score(code)`

**与 `SentimentCalculator` 的区别**：后者是市场级情绪指数（同一输入同一输出），
本因子是**个股级**（每只股票取值不同），两者不冲突、不复用。

子项与权重（合计 1.0）：

| 子项 | 权重 | 输入 | 口径 |
| --- | --- | --- | --- |
| 连板高度 `lbc_score` | 0.30 | lbc | 首板 40，每多一板递增但**边际递减** |
| 封板质量 `seal_score` | 0.25 | zbc, fund, ltsz | 炸板次数惩罚 + 封单额占流通市值 |
| 板块热度 `theme_score` | 0.25 | hybk（行业板块）| 该板块当日涨停家数占比 + 5 日轮动（历史充足时）|
| 活跃度 `activity_score` | 0.20 | hs 换手率 | 换手过低=无人问津；过高=接力风险 |

#### 连板高度分（锚点）

```
lbc_score = 40 + 25 * (1 - 0.7 ** (lbc - 1))
    lbc=1 → 40.0    lbc=2 → 57.5    lbc=3 → 66.25    lbc=4 → 71.4    lbc≥5 → 74.0（封顶）
```
边际递减的理由：连板高度是情绪强度的直接体现，但高位连板已透支涨幅，
追高的风险收益比递减。

#### 封板质量分（锚点，档位按实测分位重设）

```
炸板分（实测 n=64 分布：0→15, 1→18, 2→13, 3~5→10, ≥6→8）：
    zbc = 0 → 100
    zbc = 1 → 75
    zbc = 2 → 55
    3 ≤ zbc ≤ 5 → 35
    zbc ≥ 6 → 20        （反复打开，封不住）

封单强度分（ratio = fund / ltsz，实测 p50=0.22%、p75=1.36%、p90=3.47%）：
    fund 缺失 → None（该子项按中性 50，不当作"无封单"）
    ratio = 0        → 30
    0 < ratio < 0.1% → 50
    0.1% ≤ ratio < 0.5% → 70
    0.5% ≤ ratio < 2%  → 85
    ratio ≥ 2%        → 100

seal_score = 0.6 * 炸板分 + 0.4 * 封单强度分
```

#### 板块热度分（锚点）

```
当日强度：板块涨停家数 / 全市场涨停家数
    0        → 30      （该股所属板块当日无涨停股）
    < 3%     → 55
    3%~8%    → 72
    8%~15%   → 88
    ≥ 15%    → 100

轮动加分（历史充足时）：该板块近 5 日涨停家数均值 vs 前 5 日均值
    环比 > 1.5  → +15
    1.0 ~ 1.5   → +8
    < 1.0       → +0
    历史不足（< 10 个交易日快照）→ +0（不做时序比较）

theme_score = min(100, 当日强度分 + 轮动加分)
```

板块热度用 `hybk`（行业板块）的**当日涨停家数占比**衡量，而非绝对家数——
绝对家数会随全市场涨停总数波动（冰点期 20 家 vs 亢奋期 100 家），
占比口径在不同市场状态下可比。

#### 活跃度分（锚点）

```
换手率 hs：< 1%   → 30（无人问津）
             1%~5% → 55
             5%~15% → 85（健康接力）
             15%~30% → 70
             ≥ 30% → 45（过热/接力风险）
```
非线性且非单调：过低与过高都扣分。

#### 合成与缺失语义

```
sentiment = 0.30*lbc_score + 0.25*seal_score + 0.25*theme_score + 0.20*activity_score
```

**缺失语义（关键）**：
- 该股**不在**涨停池、也**不在**炸板池 → 返回 `None`（缺失，不是 0）
  → 归一化层按本轮修复后的语义填中性 50 分位
- 该股在池中但某个子项数据缺失（如 `fund` 缺失）→ **该子项按中性 50 计**，
  整体仍返回有效分数（部分缺失不丢弃全部信息）

覆盖率预期：情绪数据只覆盖涨停/炸板股（实测单日 39 + 25 = 64 只 / 全市场 5000+，
覆盖率约 1.3%）。**这是设计意图而非缺陷**——情绪因子天然只对短线活跃股有区分度，
非活跃股给中性 50 才是正确语义。

> 注意：炸板池的股票是"曾涨停但收盘未封住"，它们**没有 lbc（连板数）**，
> 因此 `lbc_score` 对炸板股按中性 50 计（而非首板 40）——炸板股从未封板，
> 不该享有"首板"的情绪强度。

### 4.2 市场级赚钱效应（regime 维度，不做因子）

| 指标 | 口径 | 用途 |
| --- | --- | --- |
| 赚钱效应 | `(limit_up_count - limit_down_count) / max(1, limit_up_count + limit_down_count)` | 情绪温度 |
| 晋级率 | 昨日涨停股今日涨停比例（历史不足时 None）| 情绪持续性 |
| 连板高度分布 | 各高度家数占比 | 情绪结构（高度集中在首板=普涨；集中在高板=结构性行情）|

**接入点**：`compute_overlay_weights()` 已有四层叠加（基础矩阵 → extreme_drop →
national_team → ic_multipliers），新增第 5 层 `sentiment_multipliers`：
情绪冰点时压制短线相关策略的 momentum 权重，情绪亢奋时压制（避免追高）。

**分阶段**：先只做因子（§五阶段 1），regime 维度等因子验证有效后再接（阶段 3）。

## 五、分期实施

### 阶段 1：数据层 + 因子 + 只读展示（权重 0）

| 产出 | 验收 |
| --- | --- |
| `scripts/data/sentiment_panel.py`：快照读写、涨停/炸板/题材聚合、晋级率计算 | 单测：晋级率数学锚点（构造昨日/今日池）、快照保留 60 天、首次运行降级标记 |
| `scripts/strategies/factors/sentiment.py`：4 个子项 + 合成 | 单测：每个子项的锚点值（如 lbc=1→40、lbc=3→66.25）、缺失语义 |
| 注册因子（phase=1），权重默认 0（与 analyst / cyclical 同待遇）| `get_factor_keys()` 含 sentiment；6 策略权重和仍为 1.0 |
| screener 增加可选列 `--show-sentiment` | 不加列时输出与今天完全一致（回归保护）|
| 快照落盘 + .gitignore | 快照文件不入库 |

**权重为 0 是刻意的**：加权重会改变所有策略的选股结果与回测基线。先让因子可观测、
可验证，再用数据决定权重（阶段 2），避免拍脑袋定权重。

### 阶段 2：权重灰度

- 只在 `growth_momentum`（短线/成长属性最强）加 0.05，其余因子等比缩减
- 需要跑策略表现对比（`multi_stock_backtest --update-validation`）确认 OOS 不退化
- 若退化 → 保持权重 0，把因子定位为"参考列"而非打分因子（同样是有效交付）

### 阶段 3：市场级维度接 regime

- 赚钱效应/晋级率/连板分布进 `compute_overlay_weights` 第 5 层
- 同样先只观察（输出 overlay 前后权重差异），确认方向合理再启用

## 六、降级矩阵

| 故障场景 | 行为 |

## 八、明确不做的事

| 项 | 原因 |
| --- | --- |
| 情绪因子进长线策略权重 | 长线（180 日 horizon）不做情绪交易，加权会污染校准 |
| 逐笔成交/集合竞价 | push2 逐笔反爬风险高（校准报告已列为不做）|
| 实时情绪（盘中 tick 级）| 本项目是日频选股，日频快照已够；盘中实时是另一个量级 |
| 情绪因子参与 `compute_factor_correlation_matrix` 的去相关 | 先积累样本，看它与 momentum/chip 的相关性再定 |
| 把赚钱效应做成因子 | 横截面零区分度（见 §一）|

| 风险 | 应对 |

## 十、需要拍板的决策点

1. **阶段 1 的权重定 0** —— 我建议如此（可观测、零回归风险），但这意味着阶段 1
   交付后因子**不影响选股结果**，只有参考列。是否接受这个交付形态？
2. **阶段 2 是否只改 growth_momentum 一家** —— 还是 6 策略统一加（后者对基线影响大）。
3. ~~题材热度用 ths 涨停原因字符串切分~~ —— **已解决**（§3.0）：
   改用涨停池/炸板池的结构化 `hybk` 行业板块字段，无需字符串切分，
   口径从"题材热度"改为"板块热度"（申万二级行业粒度）。
4. ~~炸板池接口待实测~~ —— **已实测**（§3.0）：`getTopicZBPool` 可用（rc=0，25 条，
   字段与涨停池同款），炸板质量可拿到真实炸板池而非退化为 zbc 字段。

### 仍需拍板

- **阶段 1 权重定 0**（因子只作参考列，不影响选股结果）—— 见 §五 阶段 1 与 §十 第 1 条
- **阶段 2 是否只改 growth_momentum 一家** —— 见 §十 第 2 条
- **板块热度用申万二级行业粒度是否够**：题材（如"机器人"）比行业更细，

  作为**补充维度**（而非替代）——但那是阶段 2 之后的增强，不是阶段 1 的必需项。
