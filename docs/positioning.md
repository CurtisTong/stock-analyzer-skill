# 项目定位（单一事实源）

> 本文件是本项目**对外定位的唯一事实源**。README、产品架构、用户指南中涉及"这是什么 / 给谁用 / 不做什么"的表述，一律以本文为准；出现冲突时改文档，不改本文。
>
> 版本：v1.33.0 | 定稿：2026-11-08 | 依据：[定位会审](#六依据与证据)

---

## 一、一句话定位

> 装进 Claude Code，每天 10 分钟做完 A 股持仓体检与复盘。

这句话同时给出三件事：**运行环境**（Claude Code 等 AI 编码代理）、**频率**（每天 10 分钟）、**动作**（持仓体检 + 复盘）。刻意不写"选股"——选股是低频一次性动作，且它的收益承诺无法被本项目的外样本验证支撑。

## 二、品类

**Agent-native 投资研究 harness**，不是选股软件。

区别在于卖什么：

| 维度 | 选股软件 | 本项目 |
| --- | --- | --- |
| 卖点 | 更准的推荐 | 可复核的分析流水线 |
| 竞争维度 | 数据覆盖、行情速度、交互 | 数据容错、推理链透明、输出稳定 |
| 失败模式 | 推荐错了 | 数据源挂了（有故障转移） |
| 结果归因 | 无法归因 | 每一步挂数据源与时间戳 |

## 三、目标用户（ICP）

**在用 Claude Code / ZCode 等 AI 编码代理的 A 股个人投资者与量化爱好者。**

准入前提写清楚：会开终端、能跑 `install.sh`。不需要会写代码，但门槛不是零——这是与"零门槛"表述的关键区别。

| ✅ 匹配 | ❌ 不匹配 |
| --- | --- |
| 已在用 AI 编码代理，想要固定研究动作 | 想要点开即用的 App |
| 持仓 3–10 只，每天看盘 5–10 分钟 | 需要 Tick 级行情或高频交易 |
| 愿意复核结论、看数据来源 | 想要直接给买卖点的荐股服务 |
| 想验证自己的判断框架 | 想要保证收益的策略 |

## 四、楔子（第一入口）

| 优先级 | 入口 | 理由 |
| --- | --- | --- |
| 主入口 | `/portfolio health` 每日持仓体检 | 高频、可重复、结果可与自己持仓变化对照 |
| 次入口 | `/market quick` 盘前/盘后复盘 | 每天有理由打开 |
| 进阶 | `/stock full` `/screener` `/research` | 深度研究，低频 |
| 工具 | `/backtest` `/learn` `/stock-help` | 按需 |

选股（`/screener`）不作为对外第一入口：单次选股的收益无法归因，且外样本表现不支持收益承诺。

## 五、护城河与反定位

**护城河**（可积累、不随模型换代清零）：

1. 37 个 fetcher × 11 数据域的故障转移
2. 五层分析 + 专家投票的**可复核输出**
3. ~2700 项测试锁住的输出稳定性
4. 核心命令零重依赖（stdlib + PyYAML）

**非护城河**（不要拿它当卖点）：模型能力、专家人设数量、策略胜率数字。

**反定位**：不做荐股、不承诺收益、不做实时行情终端、不做社区。

## 六、依据与证据

| 结论 | 证据 |
| --- | --- |
| 不能定位为"选股赚钱工具" | 策略外样本全部未达标：balanced -6.67%~-18.32%，胜率 21.4%~35.7%，`validation_status` 保持 `in_sample`（`data/strategy_oos_validation.json`） |
| 门槛不是零 | 运行依赖 Claude Code / ZCode + Python 3.11 + `install.sh` |
| 真实使用频率在持仓与复盘 | 用户画像的三类核心需求均围绕"今天持仓怎么了"，见 `docs/persona.md` |
| 差异化在工程而非模型 | 37 fetcher 故障转移、163 个测试文件、输出模板统一，见 `docs/product-architecture.md` |
